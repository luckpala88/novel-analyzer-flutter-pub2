CHAPTER 01

快速上手：整个 APP 的工作流

这个 APP 做一件事：把几百万字的网文拆成"零件"（弧线 → 场景 → 分镜），再基于零件改写成你自己的新书。

流水线总览（严格按顺序）

上传章节→ 场景页
划分场景→ 弧线页
扫描弧线→ 分镜页
拆解分镜→ 改编页
改编产物→ 世界页
世界书→ 创作页
写正文→ 二创页
质检换名

底部导航共 8 个 Tab：主页 / 场景 / 弧线 / 分镜 / 改编 / 世界 / 创作 / 二创。扫描类步骤（场景→弧线→分镜）是拆解原著；改编之后的步骤是基于拆解产物创作。平板/横屏下 8 栏并排显示，可手动分栏。

第一次使用的最短路径

  1. 主页 → 新建书目 → 上传原著 txt 章节
  2. 主页 → 随便打开一个功能页 → 顶部 ⚙ 填 API（见第 3 章）
  3. 场景页 → 设步进 → 逐弧线划分场景
  4. 弧线页 → 弧线扫描 + 分组
  5. 分镜页 → 逐场景拆分镜
  6. 改编页 → 生成改编总结/框架/分镜（顺手生成故事圣经与映射表）
  7. 世界页 → 生成世界书，创作页写正文
💡 不必一次跑完。每一步的产物都会保存，任何时候关掉 APP 都能续跑。

CHAPTER 02

主页：书目、章节与更新

管理你的所有"书"（每本书=独立的数据空间），以及章节文件和 APP 更新。

书目管理

  • 新建书目：一本书一个空间，拆解产物、世界书、创作稿互不干扰。测试时建议多建几本，坏了一本不影响别的。
  • 切换书目：点书目卡片即切换；底部导航每个 Tab 显示的都是当前书的数据。
  • 删除书目：删除前会确认。删的是数据不是源文件，txt 原文还在存储目录里。

章节上传

  • 支持 txt 纯文本，一个 txt 一个章节（文件名即章节名）。可多选批量导入。
  • 上传后按章节顺序排列；建议文件名带章节序号（如 0001.txt、0002.txt），乱序会影响扫描顺序。
  • 章节列表可直接打开进阅读器（见第 11 章），也能查看/微调正文。

检查更新

  • 点检查更新会对比 GitHub Release 上的最新版本号，有新版直接下载 APK 安装，数据不受影响。
  • 更新包下载到本地后调起安装，和普通 APK 一样确认权限即可。

存储模式

  • 公共目录：文件管理器能看到，方便拷贝迁移（推荐新手机用）。
  • 专属目录：APP 私有空间，旧手机兼容性最好。
  • 切换存储模式后建议立刻做一次备份（第 12 章）。

CHAPTER 03

API 设置（每页顶部 ⚙）

所有需要 AI 的功能，其设置都在各自页面顶部的 ⚙ 折叠面板里，每个页面独立保存，互不影响。

面板里的每个字段

字段说明
服务提供商内置：智谱 / DeepSeek / Gemini官方 / 自定义 / 自定义2。切换提供商不清 Key，每家独立保存
API Key填了 Key 后模型框自动去 /models 拉真实列表；也可手动输入模型名
模型从下拉选（自动获取），或手动填。不写死任何模型名
温度拆解扫描建议 0.3（0.1 会让 AI 偷懒合并场景，太高放飞）
输出格式文本 / JSON，一般保持默认
max_tokens上限可到 100 万，不会被 JS 截断；长章节拆解给足余量防"砍尾"
💡 常用中转/代理也能用：选「自定义」填中转地址+Key。DeepSeek 中转偶发 60 秒超时多是网络抖动，重跑即可。
⚠ 发给 AI 的内容全程零 emoji 纯文本（不给 AI 添负担）；图标和颜色只在你看到的界面上。

CHAPTER 04

场景页：划分场景

流水线第一步：把连续章节切成"场景"（最小叙事单位）。后续弧线、分镜都在场景之上做。

核心操作

  • 步进：每次让 AI 看几个章。小章书（2500字/章）设 1-2，普通章设 5-10。步进影响闭合早晚：太小闭合偏早、太大偏晚，与模型强相关。
  • 逐弧线划分：按弧线范围调 AI 输出场景切分，场景名 + 概述会展示在列表里。
  • 场景正文切片物化：划分成功后自动把弧线正文按场景边界切片，供分镜/创作引用。
  • 映射表增量抽取：场景名/概述里发现的新原著名称会自动追加到映射表（改编页可查看）。

重跑与修复

  • 对结果不满意可对单条弧线重新划分；已有场景会先备份，失败自动恢复。
  • 场景列表必须保持无丢失、无重叠、顺序对应原文——这是后面一切步骤的地基。怀疑乱了就重划该弧线。

CHAPTER 05

弧线页：扫描叙事弧线

把场景串成"弧线"（一段有头有尾的叙事单元：主角发生不可逆变化 + 叙事段收束）。

弧线扫描

  • 开始扫描：AI 按场景序列识别弧线，输出每条弧线的概述、主角、变化类型（💎不可逆变化 / 🔒闭合变化 / 🔗伪闭合）。
  • 从弧线N续扫：中断后接着扫，不用从头来。
  • 截断续扫：最后一条弧线扫到一半断了，从断点续上。
  • 扫描配方：Pro 系模型 + 温度 0.3 + 步进 10 是实测甜区；Flash 系只适合摸底试跑。

弧线分组

  • 扫描出的是"散弧"，批量分组把它们按场景/批（步进）组织成正式弧线单元（含逐弧线零件提取：人物/伏笔/冲突/脑洞等元数据）。
  • 重新生成全部弧线：清空现有分组从头发（会提示确认）。
  • 剪断重分：某条弧线内发现某场景开始剧情跑偏，可"从场景N剪断重分"——把那条弧线从该场景一剪两半分别重扫。
  • 清空重分：分组整体推倒重来。

质量校验

  • 弧线划分体检：自动查三类硬伤——丢失（有场景没被任何弧线覆盖）、重叠（场景被两条弧线重复覆盖）、顺序（弧线顺序与原文不符）。✅完整 / ⚠️不完整一目了然。
  • 弧线扫描词链预览 / 分组词链预览：发送给 AI 的实际内容预览，想确认"AI 到底看到了什么"就点它。
💡 对"伪闭合"宽容一点：拿不准就切，多切无害、漏切有害（漏切会让后续场景/分镜与原文错位）。

CHAPTER 06

分镜页：拆解分镜

把每个场景进一步拆成"分镜"（镜头级节拍：谁、在哪、干了什么）。这是最细的拆解粒度。

拆解操作

  • 按弧线/场景逐个拆，产物包含每镜的焦点、正文概要、功能位等字段。
  • 同页支持批量分组（把零散分镜归组）、续扫 / 剪断重分 / 清空重分，操作逻辑与弧线页一致。
  • 分镜结果与场景切片联动：切好的场景正文按镜级锚点定位，保证顺序不乱。
💡 分镜不必全书拆完才进改编——按需拆，改编页用到哪条弧线拆到哪条。

CHAPTER 07

改编页：总结 / 框架 / 分镜 / 圣经 / 映射表

整个 APP 的核心页。基于原著零件生成"改编后的骨架"，同时维护两样全局资产：故事圣经和名称映射表。

分层重改编（重要概念）

层级重跑范围适用场景
全层 all总结+框架+分镜 全重跑改编要求大改
弧线层 arc该弧线全部重写（级联清空）单弧线剧情重推演
场景层 scene只重写场景框架（分镜保留）框架微调
仅分镜填充 shot只重填分镜（框架不动）分镜数量/内容返工

批量入口在弧线列表：全量 / 增量可选。增量补缺=保留已有内容只补缺失项（省 API）；全量=推倒重跑。

三级产物

  1. 弧线总结条目：每条弧线的改编后概述，写入世界书（含世界观 10 体系校验补齐）。
  2. 场景框架：每场景的改编后框架（改编声明驱动）。
  3. 分镜填充：把原著分镜按新剧情逐镜重推演。数量/顺序锁死原著骨架（节奏载体），内容每镜按新剧情推演。

故事圣经

  • 全书级设定总纲（人物/世界/因果），弧线1 初始化，弧线2+ 增量回流合并新事实。
  • 圣经里的人物/设定条目按剧情使用名称：原著角色用原著原名，你因剧情需要新增的名称（写在改编要求里的）直接用新名——这两类都正常。
  • 污染的定义：映射表右列的"替换名"（原著角色被 AI 换掉后的名字）混进了圣经——那说明名字替换渗透进了中间产物，会顺数据流扩散到创作端。判断标准：一个名字出自你的改编要求=合法新名；原著角色被换成了映射表里的新名=污染。

名称映射表

  • 格式：每行 原著名 → 新名（定位）。生成端全程原著原名零损失；只有二创输出时才做换名替换。
  • 自动追加：总结/场景/分镜每步成功后自动增量抽取新名称追加（同名不覆盖，你的手改不会被冲掉）。
  • 三道防污染卫兵：①改编要求里出现的名字=新名，禁止进左列（代码级拦截，日志显示"🛡已拦截"）②已有映射表右列新名禁止被二次映射 ③AI 拿不出的别名会输出"？确认行"等你在弹窗里人工确认。
  • 起名要求：指定主角新名/命名规范，生成与增量抽取共用；写在这里的名字全部视为新名。
  • 同一角色不同称呼（婆婆/圣姑/盈盈）会映射到不同的新别称，保留原称呼的韵味——手改时也请保持这个习惯。

其他功能

  • AI 优化要求：🤖 按钮把你的大白话要求改写成结构化要求（勾选才发给 AI，也可直接手填）。
  • 字体 A- / A+：页面字号调节。
  • 日志面板（终端日志）可复制、多行选择、自动滚动到底，出错先看这里。

CHAPTER 08

世界页：世界书生成与导出

改编产物整理成"世界书"——创作的唯一依据。世界书在，创作就能继续，不依赖扫描数据。

生成

  • 一键生成：部分已生成时弹窗选 增量（只生成剩余条目）或 全量；全新直接全量。
  • 弧线内增量补缺：半成品续传，跳过已完成场景只补缺（省 API）。
  • 条目与人设一律原著原名，禁止起新名——改名统一由映射表在输出层处理。
  • 层级折叠：条目按分组折叠显示，点开看内容。

导出与查看

  • 支持 ST（SillyTavern）格式导出，可直接导入 SillyTavern 世界书使用；纯文本导出只含正文+标题，无结构标记。
  • 列表限高滚动（约 3 条高），不会把页面撑爆；章节标题全显不截断。
💡 改编后场景在世界书里优先级最高：创作列表、场景名、发送内容都以它为准。

CHAPTER 09

创作页：基于世界书写正文

选择场景/弧线，AI 依据世界书条目写改编后的正文。

主要操作

  • 单场景创作：选中场景点生成；产出挂在对应分镜块下。
  • ⚡批量：队列连续创作，可选"全部 / 仅未创作场景"；连续失败会自动终止批量并告警；随时 ⏹ 终止。
  • ✨生成分镜正文：以分镜为单位逐镜写。
  • 创作声明：可 AI 生成或手填，决定这一段怎么写（人物/冲突/作者意图等）。
  • ✎编辑 / ✓已保存：正文可直接改；保存时按分镜块定位写回，定位失败会提示（跳过写回不覆盖原稿）。
  • 写回世界书：创作结果回写条目（世界书为空时跳过并提示）。
  • ✂️ 剪切：把不要的段落从稿里剪掉。
💡 创作始终基于改编后的世界书，不会回退到原始分析数据——发现它"写回原著剧情"了，检查改编产物是否完整。

CHAPTER 10

二创页：体检与换名

最后一步：质检创作稿，并在输出时把原著名批量替换成新名。

功能清单

  • 文件列表：一创/二创文稿分开列出，支持 filter（全部/一创/二创），txt 导出（文件名自动带"_二创"后缀）。
  • 体检（detect）：AI 找问题——设定冲突、范文搬运、逻辑硬伤；结果按问题类型统计（problem_count），可一键把修改意见填进编辑框再改稿。跑体检前先确认改编页映射表已生成。
  • 换名输出：依据映射表把正文里的原著名替换成新名——这是全书唯一做替换的地方；映射表为空会提示先去改编页生成。
  • 映射表合并：⤓ 把确认行并入映射表（同名跳过），✕ 删除不采纳。
  • 二创词链预览：查看发给 AI 的内容。
  • A- / A+：字号调节。

CHAPTER 11

阅读器：翻页 / 滚动 / 朗读

从主页章节或书目进入。自带两种阅读模式和 TTS 朗读。

两种模式

  • 📑 翻页模式：电子书式，圆形 ↑↓ 按钮翻页，页边界自动跨文件接着读。
  • 📜 滚动模式：正文可编辑、可保存；编辑状态下锁定模式切换，防止丢内容。
  • 顶部信息行塞了页码+标题（不留空 AppBar）；按钮全是文字按钮（A-/A+/本页读/暂停/目录）。
  • 目录：章节跳转。本页读/暂停：TTS 朗读当前页，朗读自动跟随翻页/滚动。
💡 换字体/改字号会自动重排版分页，不用担心页码错位。

CHAPTER 12

存储、备份与数据安全

拆解一次烧不少 API 钱，数据安全请当回事。

备份

  • 主页 备份：当前书全部数据存到 backups/ 目录；全部书目备份一键备份所有书。
  • 备份格式与云同步格式和 v318 互通——旧版本备份可导入新版。
  • 建议节奏：每完成一条弧线的改编就备份一次；换存储模式后立即备份。

数据都在哪

  • 公共目录模式：文件管理器直接可见，可整目录拷走迁移。
  • 专属目录模式：需用 APP 内的备份/恢复功能迁移。
  • 删除书目只删数据不删 txt 原文。
